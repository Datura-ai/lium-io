`ContainerDeleteOnNodeLeftRequest` (backend → validator; a `ContainerDeleteRequest` with the required `expected_boot_id` and `create_command_id`, and the optional `pod_placed_on_boot_id`) and `FailedContainerErrorCodes.NotTheNodeLeft`: the delete of a moved pod's container on the node it left. The validator removes, by the inspected ID, only the pod's container labelled with this pod and `create_command_id` (`io.lium.create_command_id`); anything else under the name is kept and answered `NotTheNodeLeft`. With `expected_boot_id` set it runs only on a host whose boot id is `expected_boot_id`, and only when `pod_placed_on_boot_id` is set and is another boot (both in /proc's lowercase UUID form); otherwise it removes nothing. An empty `expected_boot_id` runs no boot check. It refuses while a create of the pod runs. `ContainerDeleted.command_id` (optional, default empty): that delete's `command_id`, echoed (also on its `FailedContainerRequest`); empty for any other delete and from older validators. A validator that does not know the type refuses the message.
