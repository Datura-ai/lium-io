# Watchtower - Automated Docker Image Update Service

Watchtower is a secure, automated service that monitors Docker images for updates, verifies their authenticity through cryptographic signatures from validators, and safely pulls and restarts containers when new versions are available.

## Features

- ✅ **Cryptographic Verification** - All image digests are verified with validator signatures using Bittensor keypairs
- ✅ **Safe Execution** - Multiple error handling layers prevent crashes on failures
- ✅ **Graceful Degradation** - Continues monitoring even if verification fails
- ✅ **Production Ready** - Infinite loop with structured logging and comprehensive error handling
- ✅ **Well Tested** - 26 unit tests covering all scenarios with 100% pass rate

## Architecture

The watchtower periodically:
1. Queries the current running Docker image digest
2. Fetches the latest authorized digest from a validator-signed endpoint
3. Verifies the signature using the validator's public key (hotkey)
4. Compares digests and pulls/restarts containers if they differ

## Installation

### Prerequisites

- Python 3.11+
- Docker daemon running
- PDM package manager

### Setup

```bash
cd watchtower

# Install dependencies
pdm install

# Copy environment template
cp .env.template .env

# Edit .env and configure:
# - WATCHTOWER_ENDPOINT_URL (your validator endpoint)
# - WATCHTOWER_VALIDATOR_HOTKEY (validator's SS58 address)
```

## Configuration

Edit `.env` file with your configuration:

| Variable | Description | Default | Required |
|----------|-------------|---------|----------|
| `WATCHTOWER_ENABLED` | Enable/disable the service | `true` | No |
| `WATCHTOWER_IMAGE` | Docker image to monitor | `daturaai/compute-subnet-executor-runner` | No |
| `WATCHTOWER_INTERVAL` | Check interval in seconds | `300` (5 minutes) | No |
| `WATCHTOWER_ENDPOINT_URL` | Validator endpoint URL | - | Yes |
| `WATCHTOWER_VALIDATOR_HOTKEY` | Validator's SS58 address | - | Yes |

### Endpoint Response Format

The validator endpoint should return JSON:

```json
{
  "digest": "sha256:abc123...",
  "timestamp": 1234567890,
  "signature": "0xabcdef..."
}
```

The signature should be generated by signing the following JSON (with sorted keys):

```json
{"digest": "sha256:abc123...", "timestamp": 1234567890}
```

## Usage

### Run Directly

```bash
cd watchtower
pdm run python src/watchtower.py
```

### Run Tests

```bash
cd watchtower
pdm run pytest tests/test_watchtower.py -v
```

### Run as a Service

#### Systemd (Recommended for Production)

Create `/etc/systemd/system/watchtower.service`:

```ini
[Unit]
Description=Watchtower - Docker Image Update Service
After=docker.service
Requires=docker.service

[Service]
Type=simple
User=your-user
WorkingDirectory=/path/to/watchtower
Environment="PATH=/path/to/watchtower/.venv/bin"
ExecStart=/path/to/watchtower/.venv/bin/python src/watchtower.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

Enable and start:

```bash
sudo systemctl enable watchtower
sudo systemctl start watchtower
sudo systemctl status watchtower
```

#### Docker Compose

Add to your `docker-compose.yml`:

```yaml
services:
  watchtower:
    build: ./watchtower
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    env_file:
      - ./watchtower/.env
    restart: always
```

### Disable Temporarily

```bash
# Set in .env file
WATCHTOWER_ENABLED=false
```

## How It Works

### Security Model

1. **Signature Generation (Validator Side)**
   - Validator generates digest from Docker registry
   - Creates JSON: `{"digest": "sha256:...", "timestamp": ...}`
   - Signs with private key
   - Returns digest, timestamp, and signature

2. **Signature Verification (Watchtower Side)**
   - Fetches response from endpoint
   - Recreates the same JSON message
   - Verifies signature using validator's public key (SS58 address)
   - Only proceeds if signature is valid

3. **Container Update**
   - Finds all running containers using the monitored image
   - Pulls the new image from registry
   - Gracefully restarts each container (10s timeout)
   - Continues to other containers even if one fails

### Error Handling

- **Network Errors**: Logs error, continues to next check
- **Invalid Signatures**: Logs warning, doesn't update, continues monitoring
- **Docker Errors**: Logs error, doesn't crash service
- **Container Restart Failures**: Logs error, continues with other containers

### Logging

Structured logging includes:
- Timestamp
- Log level
- File and function name
- Line number
- Process ID
- Detailed context (digests, container names, errors)

## Troubleshooting

### Watchtower not updating containers

1. Check if watchtower is enabled: `WATCHTOWER_ENABLED=true`
2. Verify endpoint URL is correct and accessible
3. Check logs for signature verification errors
4. Ensure validator hotkey is correct
5. Verify containers are running the monitored image

### Signature verification failing

1. Ensure endpoint returns correct JSON format
2. Verify validator is using the same message format
3. Check that validator hotkey matches the signing key
4. Ensure signature has correct `0x` prefix

### Containers not restarting

1. Check Docker daemon is running
2. Verify watchtower has permission to access Docker socket
3. Check container restart policies
4. Review logs for specific error messages
